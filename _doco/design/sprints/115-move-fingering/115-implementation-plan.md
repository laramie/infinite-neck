# Sprint 115: MovePlugin Fingering

## Goal

Add Fingering support to MovePlugin in both `playedNotes` and `recordedNotes` contexts.

## Approved Decisions

1. Add a new explicit toggle: `includeFingering`.
2. Do not piggyback Fingering onto `includeSingle` or `includeTiny`.
3. Do not modify `help-plugins.html` in this sprint.
4. Keep the existing runtime playback precedence between `playedNotes` and `recordedNotes` unchanged.

## Collision Rule For This Sprint

The persistence rule is narrower than the runtime display rule.

1. In `playedNotes`, allow at most one Fingering note per cell.
2. In `recordedNotes`, allow at most one Fingering note per beat per cell.
3. Do not attempt to prevent a `playedNotes` Fingering and a `recordedNotes` Fingering from coexisting at the same cell, because that is already a supported model state and the runtime replay layer already resolves what the user sees.

Example that remains valid:

1. User records a Fingering on beat 2 at row 4, col 2.
2. User later adds a non-recorded Fingering at row 4, col 2 while REC is off.
3. Both persist in the model.
4. Runtime playback precedence remains unchanged.

## Implementation Shape

### 1. MovePlugin property and menu updates

Update `plugins/move/properties.json` and `plugins/move/MovePlugin.js` to:

1. add `includeFingering` as a new persisted toggle
2. expose it in the include submenu
3. include it in summary/help text generated by `MovePlugin.js`
4. include it in the include-summary token shown in the menu
5. treat it as a style-selection toggle for apply no-op checks

### 2. Move helper candidate selection

Update `move-helpers.js` so that:

1. `shouldMoveStyle()` accepts `Note.STYLENUM_FINGERING` when `include.fingering` is true
2. `collectSectionData()` can select Fingering notes from both `playedNotes` and `recordedNotes`

### 3. Move helper collision handling

Update `move-helpers.js` scratch collision tracking so that:

1. played Fingering collisions are deduped per cell in `playedNotes`
2. recorded Fingering collisions are deduped per beat per cell in `recordedNotes`
3. existing played-note precedence over recorded notes remains unchanged
4. no replay-layer behavior is changed in this sprint

### 4. Note reconstruction

Verify that moved Fingering notes preserve existing Fingering payload fields, especially `finger`, while recomputing the landing `midinum`, `noteName`, `row`, and `col`.

This should already fall out of the current clone-and-rewrite implementation, but it should be covered by tests.

## Tests

Add focused Jest coverage in `_tests/jest/move-plugin.test.js` for:

1. include-summary includes the new Fingering flag
2. played Fingering is moved when `includeFingering` and `includePlayed` are true
3. recorded Fingering is moved when `includeFingering` and `includeRecorded` are true
4. moved Fingering preserves the `finger` payload
5. duplicate played Fingering landing on the same cell is dropped
6. duplicate recorded Fingering landing on the same beat/cell is dropped
7. existing played-note precedence over recorded notes still applies with Fingering present

## Non-Goals

1. Do not change `help-plugins.html`.
2. Do not change replay precedence between `playedNotes` and `recordedNotes`.
3. Do not redesign general MovePlugin collision semantics for other note styles.
4. Do not add cross-storage dedupe between `playedNotes` and `recordedNotes` for Fingering.

## Validation

Run the targeted MovePlugin Jest suite after implementation.
