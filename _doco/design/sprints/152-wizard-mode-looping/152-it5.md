# sprint-152 Iteration 5

## Round 1 Request

We need a way in tutorial `strict` mode to let the User set the BPM.

Simply, we just want to add controls to the `.tutorialPromptWidgetRow`  before the `button data-action="tutorialLoopBeats"` and after the `button data-action="tutorialLastSection"`.

At startup, and in any normal state, the control is one button, with text "30bpm" if the Song.defaultBPM is 30.  It gets its values and is live just like `#transport > .bpm` and can even ride on the class update mechanism, which would give it the same text formatting for free, e.g. 
```
<span class="bpm">30<small>bpm</small></span>
```

When that button is clicked, however, it is replaced by the controls from the File menu page:
```
<input type="text" name="txtBPM" id="txtBPM" size="4" value="80"><button type="button">✓</button>
```
though obviously a new name and id are needed, and the `value` attribute in this example just came from copying from DevTools.

On clicking the fake checkmark button, or any other loss of focus (which means it must be focused after the first button click), or other keyboard behavior already handled such as ENTER key, it sets the Song.defaultBPM (and whatever other state sets the actual BPM in the runtime).  If there are other side effects of setting the BPM from the File menu page controls, such as affecting the Looper, then the identical behaviors should be used here, hopefully by calling the shared handler. Then these controls get replaced by the original button again.
There is no "BPM:" label on the edit box and fake checkmark button for this instance.  The fact of them being where the "bpm" button was is sufficient.

This only applies in `strict` tutorial mode since in other modes this navigator/transport-substitute is not available.
