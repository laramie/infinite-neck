# Design

We need a few utilities added to the command-line menus.

In these menus `x) exit` is not shown.

Here are the menu-items shown with trigger t and caption as `t) caption` :

/se
  d) delete
  a) add
  s) shallow clone
  c) clone
  i) instrument
    I) Instrument [S6_1]
    c) clone [S6_1 into new Section 2]
    C) Clear [S6_1 from Section 1] ?
      Y) Yes: Clear S6_1 data from Section 1
      n) no: keep table data in Section 1  
  
The I) Instrument handling can be copied from how it is done in these places:
/fpaI  
/fpcI
/fpfI
/fpmI
/fpoI

The Y) versus n) question can be copied from: 
/faC

The flow into /sei would be that you would choose `I) Instrument []` first, and it would have no value in `[]` initially, 
  then would show the Instrument, the same way the plugins do.

Then the value would be filled in, and also on the lines for `c) clone` and `C) Clear`.

Note that this operates only on the current Section, and the 1-based number for the Section is shown in the User-facing text in the menu-item (Section 1).

First, the clone table flow:

You would choose c) clone [S61_1 into new Section 2] if you had chosen Instrument S6_1 and we were sitting in Section 1.


For `c) clone ....` there is no confirmation.  

However, the ! appears on the menu-item as in /sec , and the current Section is advanced (to Section 2 in our example) as it does for /sec , and the menu now offers to  c) clone [S6_1 into new Section 3]`, using the copy in Section 2, not the original in Section 1.

As always, a simple ENTER keystroke would back you out of this menu-item.

If no instrument has been chosen, the command does nothing except report in the menu result dropdown that nothing happened because no Instrument was chosen.

Now for the Clear table flow: 

Having chosen I) Instrument, we now have an Instrument, and we know the current Section.

The User would chose `C) Clear` and thus drop into the Y/n question.

If the User said `Y` ENTER, then the Section stays in the Model, but the SectionNotes, including table-level properties such as chord and mode are deleted from the Model for this Section.

So if the Model had for this Section:

```
"sections": [
    {
      "sectionNotesByTable": {
        "tblS6_1": {
         ....
        }
    ....
```            
then all of tblS6_1 goes away for this Section.

The bang ! is shown if the table data were cleared, and we are left at this same menu level.

If no Instrument is chosen, then attempting to `C) Clear....` would give a menu result in the dropdown warning that no Instrument was chosen.  The menu level stays the same, no ! is presented, and nothing changes except the menu result.

This is not in a plugin, but rather in menu.js and actions in key-handlers.js and supporting classes as makes sense, following the examples of most static menu items.

Before coding, we need to ensure that we can do this kind of value-showing of the Instrument IDs without being in a plugin.  Please provide that analysis and ask any other questions before we approve coding.

# Answers to review questions

1) For /seiI, should the instrument list include all song.myTunings, or should it filter out wired Listener/Observer tables like some plugins do? ANSWER: Filter out Listeners and Observers.  Sources of listening and observing are OK.  Also filter out such that only "visible" tables are listed. 

2) For /seic, should the new Section copy only selected table SectionNotes, or also section-level properties like rootID, beats, caption, chart settings, etc.? ANSWER: All section-level properties as though it were a deep clone, but not the other tables, (as pointed out in your response that the actual mechanism is not a deep clone).

3) If the selected table has no existing data in the current Section, should clone create an empty selected-table entry in the new Section, create a blank Section, or no-op with a warning?  ANSWER: no-op and warning.  If there are no notes, don't clone or create section.  chords and modes don't count as notes if there are no named, single, or recorded notes.

4) Should Clear bury the deleted table data in the graveyard, or simply delete it as the design text currently implies? ANSWER: great catch!  Yes, Please create a backup of the Section in the Graveyard as a SECTION record as though the Section had been deleted.

5) Should the /sei selected Instrument be session-only UI state, or persisted in the Song/plugin state? The design implies session-only and initially empty.  ANSWER: The new Section, and the modified Sections with table data removed should be in the Model state, so that if File|Download is chosen, or /vdf, we see the changes.
