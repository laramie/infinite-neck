# sprint-119 Iteration 6: Clip recordedNotes/beats

## Overview 
We have several ways of copying notes from tables, that is instruments, in infinite-neck to other tables, to other sections, etc. 

 
For all of these where we say must be in REC mode, or must not be in REC mode, if any of the conditions aren't met it's a no-op with a warning.

For all the places we say "warning" we mean the command result that ends up in the command-line dropdown.  For voluminous messages, we do showMessages, but all the warnings in this Iteration should fit in the command result.


## New section edit instrument clone

In addition to existing `/seic` :: "section > edit > instrument > clone",  we need to add `/seii` :: "section > edit > instrument > insert clone table into other section" > "INPUT> 1-based-section-number". This would be with an INPUT for the section number, similar to how we deal with it in `/rsg` including the prompt with `n+1`. If destination table is not empty in that section, or if section doesn't exist, this is a no-op with a warning.


## ClipPlugin new verbs

Then we need to add some verbs to ClipPlugin.  At the main level `/fpc` we would start with a menu item called `r) recorded notes` and then drop into there. Next we would see copy or paste, and so on, as shown in "Proposed Menu Structure".

Selecting one of `c) copy` > `a) all beats` would copy all notes in all the recorded beats.

Selecting one of `c) copy` > `c) current beat` would copy all notes in the current beat.

There is no flow for selecting the note type. The note type menu-item from `/fpci` is ignored.  In this whole new clip plug-in flow we are describing in this Iteration 6, we grab all note types: there is no no type filtering. 

The user would then traverse to the section and beat location where they wanted to begin pasting. 

The user would select REC mode or not with the button on the transport. 

For this iteration, we are only doing tables with same Lineage, so it could be a different table, but n-strings and midiPitiches must line up. This means that we are not doing MIDI Paste, and that cells line up (same string/row, and col, for same pitch).  This means they would have come back in through ClipPlugin and changed Instrument.  That is part of the valid state when comming back into the paste in `/fpcrp`

The User would drop into `/fpcrp` and select menus for the following scenarios below.

At this point the user is ready to paste beats either in REC mode or not REC mode, and they are at the current section, the current beat, and have a destination table selected that is compatible with the Lineage of the source table where the current Clip is from.  

We now consider that the user has a set of beats in the Clip memory and each beat contains recorded notes. We'll call this the source set. 

Remember that the User was in charge of deciding if the source set was one beat, or many beats.  However, the actual number, if not "current beat", was actually the number of beats in the source Section.

The source set could have, say, four beats with multiple types and instances of notes each.  

So we want to support several types of scenarios around number of beats in the source set and the number of beats in the destination. 

### First scenario. "play beats into current" when source set has one beat

For this scenario REC must be on. 

Take the only beat from the source set and play it into the current beat overwriting notes of the same note type and cell that are already there, replacing notes upon collision. This is important because the new note might have a different color or roll. We want the new note.  

### Second scenario. "play beats into current"

For this scenario REC must be on. 

Starting with the current beat in the destination, that is the current section, take the first beat of the source set and play the beats into the current beat overwriting collisions, and advancing beats so that one beat from the source set hits one beat in the destination set.  Both advance one until we exhaust the possibility of having a source match up with a destination. When we run out of source set beats we stop. If we run out of destination beats we stop -- we don't create any new beats.

Examples, showing one note per beat, and current beat with one note F as *F* to start:

source (4 beats):  A B C D
destination (3 beats): E *F* G
result (3 beats): E *FA* GB

source (4 beats):  A B C D
destination (1 beat): *F*
result (1 beat): *FA*

source (4 beats):  A B C D
destination (4 beat): *F* G A B
result (4 beats): *FA* GB AC BD

source (1 beat):  A
destination (4 beat): E *F* G B 
result (4 beats): E *FA* G B

### Third scenario. "squeeze beats into current beat"

For this scenario REC must be on. 

Take all the beats in the source set and play them into the current beat replacing any notes that are collisions.

Examples: 

source (4 beats):  A B C D
destination (3 beats): E *F* G
result (3 beats): E *FABCD* G

### Fourth scenario "add all beats"

For this scenario REC must be on. 

For this scenario, all beats in the source set will end up in the destination section as new beats. We start after the current beat in the destination, and so insert/append. No overwriting occurs because we either insert after the current beat, or we are spending after the last beat.

source (4 beats):  A B C D
destination (3 beats): E *F* G
result (7 beats): E *F* A B C D G

### Fifth scenario. "insert all beats"

For this scenario REC must be on. 

Same as "add all beats" but instead of after the current beat we start *before* the current beat.

source (4 beats):  A B C D
destination (3 beats): E *F* G
result (7 beats): E A B C D *F* G

### Non-scenario. "grab some beats"

For a scenario where User wants to grab just 3 beats from current section with 5 beats, he will instead copy or clone beats into new section, delete beats there, preview, then copy all. This is a separate, manual flow we won't deal with.

### Sixth scenario. "flatten beats into playedNotes"

For this scenario REC must be off. 

Play all notes in the source set, that is to say, all the beats in that source set, in order, into the current section but not in REC mode, with Multi highlight last. Therefore they all become played notes. 

For "flatten beats into playedNotes", the order is important. First SingleNotes, TinyNotes, and Bends, then Pitch then Multi. This way, Multi wins over Pitch, although both Midi types (Pitch and Multi) will be lost on navigation etc.  But for the moment after the paste, the user can see Pitch if present, or Multi if present, and if both, then they say Multi if present. Result message should succinctly mention that Highlights will be lost on navigation if they are present.  Message format: `Pitch/Multi are temporary` but using the sum of which were included, e.g. `Pitch`, `Pitch/Multi`, `Multi`.  The result line may get long for the dropdown, but we are going to clean these up in a later sprint.

source (4 beats):  A B C D
destination (3 beats): E *F* G
result (3 beats):  E *F* G
BUT: playedNotes: [A,B,C,D]


## Proposed Menu Structure

Menu structure is shown indented, with format `t) caption` where t is the trigger, and caption is the caption text, and t is bolded in caption. For existing lines, we are not showing the trigger, so they would just have the format `clear clipped notes`.

In the examples, when you see array brackets, it means a default filled in by the system, and we may show example text, for example: 
`    Instrument [P46_1]`
because P46_1 was the value that was true when this menu was captured.

Some lines start off with path, shown as `/fpc` which would mean `/` `file` `plugins` `clip` in the command-line menu.

In all menus, `e<b>x</b>it` is ommitted but would be present because it is constructed by the system.

Here is what we have today:
```
/fpc
    Bury
    Instrument [P46_1]
    C copy
    X cut
    V paste [12:tiny-4-0107]
    MIDI Paste [14:tiny-4-0107]
    L copy Listened notes
    automatic [true]
    overwrite [true]
    include [n:0,s:0,t:4,b:0,f:0]
    clear clipped notes
    help
```

Here is what we'll have after implementation of sprint-119 Iteration 6:
```
/fpc
    Bury
    Instrument [P46_1]
    C copy
    X cut
    V paste [12:tiny-4-0107]
    MIDI Paste [14:tiny-4-0107]
    L copy Listened notes
    automatic [true]
    overwrite [true]
    include [n:0,s:0,t:4,b:0,f:0]
    r) recorded notes
        c) copy
            status: [tblname:sectionNum:beatnum]
            c) current beat - copy
            a) all beats - copy
        p) paste
            status: [tblname:sectionNum:beatnum]
            a) add all beats
            i) insert all beats
            p) play beats into current
            s) squeeze beats into current beat
            f) flatten beats into playedNotes
    clear clipped notes
    help

```  

The special line `status: [tblname:sectionNum:beatnum]` is informational, and has no trigger or bolded letter.  You can see an example that would apply if you look in `/fm` where we show the current mapping of the spacebar in the first menu item `current: []`
